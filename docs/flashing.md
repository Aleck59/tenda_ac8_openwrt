# Запуск и прошивка Tenda AC8 v1

Порядок важен: **резервная копия → запись во флеш → проверка**.
Переходите к следующему шагу, только если предыдущий прошёл.

Что понадобится:

- USB-UART адаптер на **3,3 В** (CP2102, CH340, FT232). 5 В сожгут SoC;
- программатор CH341A и клипса SOIC-8. Без них восстановить роутер после
  ошибки при записи загрузчика не получится;
- TFTP-клиент на ПК (`tftp-hpa` в Linux, `tftp` в Windows), если шить
  из загрузчика без программатора;
- для 8/16 МБ — новая микросхема SPI NOR на 3,3 В, например W25Q64JVSIQ
  (8 МБ) или W25Q128JVSIQ (16 МБ).

## 1. Резервная копия флеша

Снимите полный дамп оригинальной микросхемы **дважды** и сравните:

```sh
flashrom -p ch341a_spi -r ac8-stock-1.bin
flashrom -p ch341a_spi -r ac8-stock-2.bin
sha256sum ac8-stock-*.bin      # суммы должны совпасть
```

Храните дамп в надёжном месте. В нём загрузчик, MAC-адреса и калибровка
радио вашего экземпляра, взять их больше неоткуда.

Проверьте, что раскладка совпадает с той, на которую рассчитана сборка.
По смещению `0x20000` должен начинаться заголовок `cs6c` (или `cr6c`):

```sh
dd if=ac8-stock-1.bin bs=1 skip=$((0x20000)) count=16 2>/dev/null | xxd
# 00000000: 6373 3663 ....        cs6c....
```

Если там другое, **не шейте**: раскладка вашей ревизии отличается, и
сначала нужно поправить DTS и профиль образа по дампу и логу загрузки.

## 2. UART и загрузчик

На плате есть 4-контактный разъём UART (GND, TX, RX, VCC). VCC **не
подключайте**. Скорость загрузчика Realtek обычно 38400 или 115200,
ядро OpenWrt выводит лог на 115200.

При включении питания жмите `Esc` в терминале. Должно появиться
приглашение `<RealTek>`. Команда `?` выводит список команд.
Сохраните весь лог загрузки стоковой прошивки: по нему видно модель
флеша, объём ОЗУ и какие микросхемы найдены.

Загрузчик работает как TFTP-сервер, обычно на `192.168.1.6`. Задайте ПК
адрес `192.168.1.100/24` и подключите кабель в LAN-порт.
Адрес загрузчика меняется командой `IPCONFIG <ip>`.

## 3. Запись во флеш

В профилях 8 и 16 МБ OpenWrt пишет во флеш только в область прошивки
(`0x20000` до конца без последних 128 КБ); загрузчик с данными платы
остаётся недоступным. Настройки хранятся в JFFS2 после SquashFS
(`rootfs_data`) и переживают перезагрузку, обновление делается из LuCI.

Сборки до `ac8-20260924-8` включительно монтировали флеш только для
чтения: на эту версию переходите программатором (вариант А) или из
загрузчика (вариант Б). Дальше — из LuCI (вариант В).

### Вариант А: программатор (первая установка, замена микросхемы)

В Releases есть готовый `*-{8m,16m}-fullflash.bin`: загрузчик из
`boot/tenda_ac8-v1-boot.bin` репозитория + OpenWrt на всю микросхему
(см. [boot/README.md](../boot/README.md)). Его можно целиком записать на
чистую новую микросхему:

```sh
flashrom -p ch341a_spi -w openwrt-*-tenda_ac8-v1-16m-fullflash.bin
```

То же самое локально из полного дампа, скриптом
[`scripts/make-fullflash.py`](../scripts/make-fullflash.py) из репозитория:

```sh
python3 make-fullflash.py \
    --backup ac8-stock-1.bin \
    --firmware openwrt-*-tenda_ac8-v1-16m-squashfs-sysupgrade.bin \
    --size 16M --output ac8-openwrt-16m-full.bin
flashrom -p ch341a_spi -w ac8-openwrt-16m-full.bin
```

Скрипт берёт из дампа загрузчик (первые 128 КБ) и кладёт образ OpenWrt
по смещению `0x20000`. Для новой микросхемы выполните это до пайки, для
стоковой — на месте клипсой.

Обновить только прошивку, не трогая загрузчик: `make-fullflash.py` без
`--backup`/`--boot` делает образ размером с микросхему и файл `.layout`,
который пишется по регионам:

```sh
python3 make-fullflash.py --firmware openwrt-*-8m-squashfs-sysupgrade.bin \
    --size 8M --output ac8-update-8m.bin
flashrom -p ch341a_spi -l ac8-update-8m.bin.layout -i firmware -w ac8-update-8m.bin
```

Так меняется только область `firmware` (`0x20000` до конца без последних
128 КБ). Без `-l ... -i firmware` загрузчик будет стёрт.

### Вариант Б: из загрузчика (без программатора)

Загрузите `*-squashfs-sysupgrade.bin` в RAM по TFTP. В консоли загрузчика:

```text
<RealTek>AUTOBURN 0
<RealTek>LOADADDR 80a00000
```

`AUTOBURN 0` обязательно: иначе загрузчик сам начнёт писать принятый
образ во флеш. На ПК:

```sh
tftp -m binary 192.168.1.6 -c put openwrt-*-tenda_ac8-v1-8m-squashfs-sysupgrade.bin
```

Затем запишите образ командой `FLW`:

```text
<RealTek>FLW 20000 80a00000 <размер_файла_hex> 0
```

- `20000` — смещение во флеше, **не меньше `20000`**: ниже лежит загрузчик;
- размер — длина файла в hex (`printf '%x\n' $(stat -c %s файл)`);
- загрузчик попросит подтверждение.

Автозапись (`AUTOBURN 1` + `tftp put`) для этого образа не проверялась:
загрузчик Realtek может записать только сегмент ядра с заголовком
`cs6c` и пропустить SquashFS за ним.

### Вариант В: из LuCI (обновление с этой версии)

**Система → Резервное копирование / Прошивка → Установить новую
прошивку**, файл `*-squashfs-sysupgrade.bin` своего профиля (8 или 16 МБ).
«Сохранить настройки» работает. Из консоли то же самое:

```sh
sysupgrade /tmp/openwrt-realtek-rtl8197f-tenda_ac8-v1-8m-squashfs-sysupgrade.bin
```

Запись во флеш на AC8 работает через экспериментальный драйвер порта.
Первый признак, что она исправна, — настройки остаются после
перезагрузки. Если обновление оборвётся, загрузчик останется целым:
восстановление — вариантом Б или А.

## 4. Проверка после загрузки

Адрес роутера — `192.168.1.1/24`, DHCP-сервер на LAN включён: на ПК
оставьте получение адреса автоматически (DHCP), ПК получит адрес из
`192.168.1.100…249`. Статический адрес `192.168.1.1` на ПК занимать
нельзя — это адрес роутера. Wi-Fi включается сам в конце загрузки:
SSID `Openwrt`, WPA2-PSK, пароль `12345678`.

Ядро выводит лог в UART на 115200. После загрузки проверьте:

```sh
cat /proc/cpuinfo                        # system type: RTL8197F
cat /proc/mtd                            # boot, firmware, tenda_config
dmesg | grep -iE 'rtl819x|8367'          # драйверы Ethernet и коммутатора
swconfig dev switch0 show | grep -E 'link|vlan|ports'
ip -br link                              # eth0, eth0.1 (WAN), eth0.2 (LAN)
cat /proc/bus/pci/devices                # 10ec f812 = RTL8812F
```

Подключите кабель по очереди в каждое гнездо и посмотрите, на каком порту
коммутатора появляется линк (`swconfig dev switch0 show`): порты 0–3 —
LAN, порт 4 — WAN. Сохраните весь лог: по нему правится DTS.

### Ethernet

С `ac8-20260926-19` Ethernet работает на драйверах из порта OpenWrt для
D-Link DIR-842 R1: у него тот же SoC и коммутатор с тем же ID, что у AC8, и
гигабит там проверен. `rtl819x` ведёт CPU-порт SoC: CPU-тег коммутатора
вставляет и снимает сам SoC, LAN приходит как `eth0.2`, WAN — как
`eth0.1`. Коммутатор настраивает swconfig-драйвер `rtl8367b`: он не
сбрасывает чип и оставляет RGMII-канал, который поднял загрузчик
(сброс с частичной переинициализацией и давал «линк есть, данных нет»).

Сторону SoC драйвер настраивает сам: загрузчик гасит тактирование switch
core перед запуском ядра, и его настройка порта P0 теряется. С
`ac8-20260926-20` задержки RGMII по умолчанию как в стоке AC8: SoC — TX 0,
RX 7, `CF_SEL_RGTXC` 3; коммутатор — TX 0, RX 2 (их ставит загрузчик).

В логе загрузки должно быть:

```
RTL8367S: loader-configured uplink (0x1219=0040) — preserving power-on RGMII trunk
applied Tenda AC8 OEM LED/threshold/SSC sequence
rtl819x-eth ...: P0GMIICR=00037d00 at probe (not configured): RGMII TX delay 0, RX delay 7, RGTXC 3; pads written
rtl819x-eth ...: switch core reset (FULL_RST + clock cycle + table SRAM init)
rtl819x trunk-post: ...
```

#### Подбор задержек RGMII: `ac8-trunk`

Если линк есть, а данных нет, задержки обеих сторон канала SoC ↔
коммутатор подбираются на ходу, без перепрошивки. Нужна консоль UART.

1. Подключите ПК к LAN-гнезду, задайте ему адрес `192.168.1.2/24` и
   запустите на нём `ping -t 192.168.1.1` (Linux: `ping 192.168.1.1`).
   Этот пинг нужен только для проверки приёма (коммутатор → роутер).
2. На роутере: `ac8-trunk test`. Передача (роутер → коммутатор)
   проверяется без ПК: драйвер отправляет 200 тестовых кадров, коммутатор
   считает их на порту 6 — целые и с ошибками CRC. Приём: сколько кадров
   коммутатор отправил роутеру и сколько из них получил `eth0`.
3. Если хотя бы одно направление `FAIL`: `ac8-trunk sweep` (около 3 минут)
   перебирает задержки и оставляет рабочие. Потом снова `ac8-trunk test`.
4. `ac8-trunk save` — сохранить значения (`/etc/ac8-trunk.conf`, переживает
   перезагрузку и обновление); `ac8-trunk reset` — вернуть значения
   прошивки после перезагрузки.

Вручную: `ac8-trunk soc TX RX [RGTXC]` (SoC: TX 0–1, RX 0–7, RGTXC 0–3),
`ac8-trunk sw TX RX` (коммутатор: TX 0–1, RX 0–7), `ac8-trunk` без
аргументов показывает регистры обеих сторон. Всё это — обёртка над
`/proc/rtl819x_trunk`. Пришлите вывод `ac8-trunk sweep` и
`/tmp/ac8-trunk.log`: рабочие значения войдут в прошивку по умолчанию.

Если Ethernet не работает, пришлите `dmesg` целиком и вывод:

```sh
ac8-trunk
ac8-trunk test
swconfig dev switch0 show
ip -s link show eth0
cat /proc/rtl865x_fabric
```

### Wi-Fi

Wi-Fi-драйвер `rtl8192cd` вендорский и экспериментальный. Он работает
через cfg80211/nl80211, поэтому радио видны в LuCI, `iw` и
`/etc/config/wireless`, а точку доступа поднимают netifd и hostapd.

Драйвер загружается сам в конце загрузки системы
(`/etc/init.d/rtl8197f-wlan`): встроенное радио 2,4 ГГц (`wlan0`) и
RTL8812F 5 ГГц на PCIe (`wlan1`). Проверьте:

```sh
cat /tmp/rtl8197f-wlan-load.log   # вывод загрузки драйвера
cat /proc/bus/pci/devices         # 10ecf812 — RTL8812F на PCIe
dmesg | grep -i pci               # запуск шины PCIe
iw dev                            # phy0/phy1, интерфейсы wlan0, wlan1
```

Радио, которые драйвер нашёл впервые, `wifi config` добавляет в
`/etc/config/wireless` включёнными: SSID `Openwrt`, WPA2-PSK, пароль
`12345678`, страна `RU` (значения по умолчанию из `/etc/board.json`).
Поменяйте их в **Сеть → Беспроводные сети**. Настройки, сохранённые
при обновлении со сборок до `ac8-20260925-16` включительно, остаются
как были (радио выключены); чтобы получить новые значения, обновитесь
без сохранения настроек или удалите `/etc/config/wireless` и выполните
`wifi config && wifi up`.
Интерфейсы называются как в прошивках Realtek: `wlan0`, `wlan1` — первая
точка доступа радио, `wlan0-1`, `wlan0-2` и т. д. — дополнительные SSID
и клиент.

Если драйвер уронит или подвесит роутер, в `/etc` останется метка
`rtl8197f-wlan.loading` с режимом загрузки. Следующая загрузка запишет
этот режим в `/etc/rtl8197f-wlan.failed` и попробует следующий: сначала
`dual` (оба радио), затем `pcie` (только 5 ГГц). Когда не осталось ни
одного, Wi-Fi не включается, а LAN и LuCI работают. Пришлите лог UART с
падением. Повторить загрузку:

```sh
rm /etc/rtl8197f-wlan.failed
/etc/init.d/rtl8197f-wlan start
```

Вручную (после `/etc/init.d/rtl8197f-wlan disable` и перезагрузки):
`rtl8197f-wlan-load --dual`, `--pcie` (только 5 ГГц) или без параметра
(только 2,4 ГГц).

Отключить автозагрузку: `/etc/init.d/rtl8197f-wlan disable`. Без
калибровки из стоковой прошивки мощность и чувствительность могут быть
заметно хуже.

## 5. Возврат на стоковую прошивку

Запишите сохранённый дамп программатором:

```sh
flashrom -p ch341a_spi -w ac8-stock-1.bin
```

Если микросхема заменена на 8/16 МБ, дополните дамп байтами `0xFF` до
размера микросхемы (flashrom требует точный размер) и запишите его:

```sh
cp ac8-stock-1.bin ac8-stock-16m.bin
head -c $((16*1024*1024 - 4*1024*1024)) /dev/zero | tr '\000' '\377' >> ac8-stock-16m.bin
flashrom -p ch341a_spi -w ac8-stock-16m.bin
```

Или впаяйте обратно оригинальную микросхему.
