# OpenWrt для Tenda AC8 v1

Сборка OpenWrt 24.10 (Linux 6.6) для роутера Tenda AC8 v1 на SoC Realtek
RTL8197FH через GitHub Actions.

> **Статус: экспериментальный.** В официальной OpenWrt нет поддержки
> RTL8197F. Сборка использует сторонний, ещё не завершённый порт этого SoC.
> На Tenda AC8 её пока никто не запускал. Прежде чем что-то шить,
> прочитайте [docs/flashing.md](docs/flashing.md) и сделайте полный дамп
> флеша программатором.

## Железо

| Узел | Микросхема | Примечание |
|---|---|---|
| SoC | Realtek RTL8197FH, MIPS 24Kc 1 ГГц | встроенное радио 2,4 ГГц 802.11n 2×2 |
| 5 ГГц | Realtek RTL8812FR (PCIe) | 802.11ac 2×2 |
| Коммутатор | Realtek RTL8367RB | 1 WAN + 3 LAN, гигабит |
| Флеш | SPI NOR 4 МБ | можно заменить на 8/16 МБ |
| ОЗУ | 64 или 128 МБ | в DTS указано 64 МБ |
| Сток | eCos, образ `cs6c` по адресу `0x20000` | загрузчик Realtek в `0x0–0x20000` |

Раскладка стока и набор микросхем взяты из разбора прошивки AC8 V2.0
(`US_AC8V2.0re_V03.03.10.01`): заголовок `cs6c`, `burnAddr 0x20000`,
`startAddr 0x80700000`, таблицы RTL8812F, драйвер rtl8367b/rtl8367c.
Прошивку v1 найти не удалось, поэтому раскладку нужно сверить с дампом
(см. [docs/flashing.md](docs/flashing.md)).

## Что работает, а что нет

Сборка основана на порте
[tobyw121/Openwrt_RTL](https://github.com/tobyw121/Openwrt_RTL)
(ветка `RT8197F`, каталог `openwrt24.10-realtek-rtl8197f-mw5`).
В нём есть профили Xiaomi R4 (RD05), Tenda AC23 и Tenda Nova MW5.
Этот репозиторий добавляет к ним профиль Tenda AC8 v1.

| Функция | Состояние |
|---|---|
| Загрузка ядра, UART, консоль | на AC8 v1 (флеш 8 МБ) загрузчик стартует образ с `0x20000`, ядро загружается |
| Ethernet (RTL8367RB через DSA) | LAN работает: LuCI открывается с ПК в LAN-порту. Драйвер SoC ведёт AC8 по пути Xiaomi RD05, задержки RGMII и тег `rtl8_4t` подобраны на AC8 v1 скриптом `ac8-ethtest` и зашиты в DTS. WAN ещё не проверялся. Если на другом экземпляре LAN не заработает, `ac8-ethtest` подберёт значения заново (см. [docs/flashing.md](docs/flashing.md)) |
| Wi-Fi 2,4 + 5 ГГц | вендорский драйвер `rtl8192cd`, перенесённый на Linux 6.6, вместе со слоем cfg80211/nl80211 Realtek, перенесённым на cfg80211 из mac80211 backports 6.12. Радио видны в LuCI (**Сеть → Беспроводные сети**), точку доступа поднимают netifd и hostapd (`wpad-basic-mbedtls`). Драйвер грузится после загрузки системы (`/etc/init.d/rtl8197f-wlan`); если загрузка обоих радио не завершилась, следующая загрузка пробует только 5 ГГц, затем Wi-Fi выключается. В сборках до `ac8-20260925-15` включительно радио не находились: ядро собиралось без PCI, а встроенное радио драйвер не запускал. На AC8 ещё не проверен |
| Флеш | в профилях 8/16 МБ запись разрешена только в область прошивки (загрузчик защищён драйвером): настройки хранятся в JFFS2 (`rootfs_data`), обновление — `sysupgrade` или LuCI. Драйвер записи экспериментальный, на AC8 ещё не проверен. Профиль 4 МБ — только чтение |
| LuCI | тема по умолчанию — [footstrap](https://github.com/VizzleTF/luci-theme-footstrap) (v0.14.13), обновление прошивки из LuCI |
| Светодиоды и кнопка | GPIO из стоковой прошивки AC8 v1: SYS — A6, WPS — A7, кнопка WPS/RST — C4 (короткое нажатие — перезагрузка, от 5 с — сброс настроек). WLAN — E1, работает. Светодиоды портов LAN/WAN ведёт коммутатор RTL8367RB, режим задаётся так же, как в стоке. SYS и WPS на AC8 ещё не проверены |
| Перезагрузка | `reboot` перезапускает SoC через сторожевой таймер |

Сборка годится, чтобы проверить железо и довести порт. Как основная
прошивка роутера она пока не подходит: Wi-Fi на AC8 ещё не проверен.

### Почему OpenWrt 24.10, а не 25.12

В OpenWrt 25.12 и `main` поддержки RTL8197F нет: цель `realtek` там
только для коммутаторов RTL83xx/RTL93xx. Единственный современный порт
RTL8197F сделан на OpenWrt 24.10 и ядре 6.6. Переход на 25.12 (ядро 6.12)
означает перенос платформенного кода и драйверов этого порта. Это
отдельная задача, и делать её имеет смысл после проверки на железе.

### Исходники Mercusys MR62X

[GPL-архив MR62X](https://static.mercusys.com/gpl/mr62xv1_gpl.tar20240319110758.gz)
(1,2 ГБ) — это Realtek SDK, оформленный как «openwrt-21.02». В нём:

- ядро **Linux 4.4** и вендорский тулчейн msdk (uClibc 0.9.33);
- вырезанное дерево OpenWrt: ядро, Wi-Fi-драйверы, U-Boot и opkg,
  без пакетов OpenWrt. Пользовательская часть — закрытая прошивка
  TP-Link/Mercusys;
- конфигурация под SPI NAND и Wi-Fi 6 RTL8832BR, а в AC8 стоят
  SPI NOR и RTL8812FR.

Как основа для «чем новее, тем лучше» он не годится. Как справочник
полезен: в MR62X тот же коммутатор RTL8367RB, подключённый к GPIO H0/G7
по SMI и к CPU-порту по RGMII. Эти значения и использованы в профиле AC8.

## Профили и объём флеша

| Профиль | Флеш | Окно прошивки | Для чего |
|---|---|---|---|
| `tenda_ac8-v1` | 4 МБ (сток) | 3,75 МБ | прошивка не помещается; по умолчанию не собирается |
| `tenda_ac8-v1-8m` | 8 МБ | 7,75 МБ | установка во флеш |
| `tenda_ac8-v1-16m` | 16 МБ | 15,75 МБ | установка во флеш, рекомендуется |

Размеры в текущей сборке: ядро с загрузчиком — 2,8 МБ, SquashFS с LuCI
и Wi-Fi — 3,3 МБ, образ во флеш — 6,3 МБ. Даже без LuCI и Wi-Fi выходит
4,9 МБ, а на стоковой микросхеме под прошивку есть 3,75 МБ, поэтому для
4 МБ образов нет. Для установки ставьте
16 МБ (W25Q128JVSIQ, GD25Q128) или 8 МБ (W25Q64JVSIQ). Загрузчик Realtek
определяет микросхему по JEDEC ID, 3-байтной адресации хватает до 16 МБ.

## Сборка в GitHub Actions

1. **Actions → Build OpenWrt (Tenda AC8 v1) → Run workflow.**
2. Параметры:
   - `devices` — какие профили собирать (по умолчанию 8 и 16 МБ);
   - `extra_packages` — дополнительные пакеты через пробел;
   - `release` — выложить образы в GitHub Releases (включено по умолчанию);
   - `packages` — собрать ещё все модули ядра и выложить фид пакетов
     `<версия>-packages` (выключено по умолчанию, +~17 минут, см. ниже).
3. Готовые файлы — в **Releases** (предварительный выпуск `ac8-<дата>-<номер>`)
   и в артефакте `openwrt-tenda-ac8-<номер>` на странице запуска.

Сборка запускается и сама при push в `main`, если меняются `configs/`,
`overlay/`, `patches/`, `base.env` или скрипты сборки. Результат такой
сборки тоже публикуется в Releases, фид пакетов она не собирает.

Раннер публичного репозитория — 4 ядра, сборка идёт в `make -j4`.
Первая сборка занимает ~55 минут: 35 из них — host-tools и тулчейн.
Они кешируются между запусками (как и архивы исходников), поэтому
следующие сборки идут ~23 минуты, с `packages` — ~40 и ещё 10–15 минут
на выкладку фида. Кеш сбрасывается при смене `base.env`, цели или
настроек компилятора; смена пакетов и опций ФС его не трогает.

## Файлы на выходе

В Releases публикуются только два вида файлов, контрольные суммы — в
тексте выпуска:

| Файл | Назначение |
|---|---|
| `*-{8m,16m}-fullflash.bin` | полный образ микросхемы **с загрузчиком** из `boot/tenda_ac8-v1-boot.bin` (см. [boot/README.md](boot/README.md)); пишется целиком: `flashrom -p ch341a_spi -w` |
| `*-{8m,16m}-squashfs-sysupgrade.bin` | обновление из LuCI/`sysupgrade`: заголовок `cs6c`, загрузчик LZMA с ядром, SquashFS, маркер JFFS2 и метаданные; можно записать и с `0x20000` из загрузчика |

Образ размером с микросхему из своего дампа или только для региона
`firmware` делает [`scripts/make-fullflash.py`](scripts/make-fullflash.py).

Как запускать и шить — [docs/flashing.md](docs/flashing.md).

## Пакеты

Прошивка сразу настроена на источники пакетов
(`/etc/opkg/distfeeds.conf`, **Система → Программное обеспечение** в LuCI):

- **официальный OpenWrt 24.10.8 для `mipsel_24kc`** — программы,
  библиотеки и приложения LuCI. Цель `realtek/rtl8197f` официально не
  собирается, но у архитектуры `mipsel_24kc` те же версии libc, libubox,
  libubus, libuci и mbedtls, что в этом порте;
- **фид `tenda_ac8`** — модули ядра, Wi-Fi-драйвер, `base-files`, тема
  footstrap; только в прошивках, собранных вручную с `packages`. Модули
  собираются вместе с прошивкой (иначе не совпадёт версия ядра), и
  [`packages.yml`](.github/workflows/packages.yml) выкладывает их
  релизом `<версия прошивки>-packages`. У остальных сборок модулей ядра
  для установки нет: нужное должно быть в образе.

Подробности — [docs/packages.md](docs/packages.md).

## Локальная сборка

Нужен Linux с [зависимостями сборки OpenWrt](https://openwrt.org/docs/guide-developer/toolchain/install-buildsystem).

```sh
./scripts/prepare.sh openwrt           # исходники порта + патчи AC8 + feeds
./scripts/configure.sh openwrt "tenda_ac8-v1 tenda_ac8-v1-16m"
cd openwrt
make download -j8
make -j"$(nproc)"
ls bin/targets/realtek/rtl8197f/
```

```

configs/kmods-exclude.txt модули ядра, которые не собираются (нет такого железа)
configs/packages.env      официальный выпуск OpenWrt для пакетов в образах
overlay/                  новые файлы поверх дерева (DTS платы, конфиг Wi-Fi)
patches/                  изменения файлов порта (образы, сеть, загрузчик, Wi-Fi)
scripts/prepare.sh        скачивает дерево, накладывает overlay и патчи, ставит feeds
scripts/configure.sh      пишет .config и проверяет, что профили не выпали
scripts/distfeeds.sh      фиды opkg в образе

docs/packages.md          откуда ставятся пакеты и как собирается фид
docs/release-notes.md     текст, который публикуется с каждым релизом
```

Что добавлено к порту:

- `overlay/target/linux/realtek/dts/rtl8197f_tenda_ac8-v1*.dts[i]` — плата:
  коммутатор RTL8367RB (SMI на GPIO 56/55, CPU-порт 6, RGMII), PCIe для
  RTL8812FR, флеш на 4/8/16 МБ в режиме только чтения;
- `0001` — загрузчик LZMA останавливает watchdog и пишет в UART RTL8197F;
- `0002` — профили образов `tenda_ac8-v1`, `-8m`, `-16m`;
- `0003` — сеть по умолчанию: `lan1..lan4` в `br-lan`, `wan` отдельно;
- `0004` — вариант Wi-Fi-драйвера `kmod-rtl8192cd-rtl8197f-ac8`
  (RTL8197FH + RTL8812F) со своим `config_8192cd_ac8.h`. В порте зашит
  конфиг Tenda MW5 (RTL8822B), и варианты с 8812F не линковались;
- `0005` — исправление сборки драйвера без поддержки 8198F/8814B;
- `0006` — драйвер Ethernet SoC (`rtknet`) ведёт AC8 по тому же пути, что
  Xiaomi RD05 (RTL8197FH-VG + внешний RTL8367 на P0/RGMII): настройка
  P0/RGMII, таблицы внутреннего коммутатора SoC, перезапуск DMA-колец.
  Без этого на AC8 адреса колец оставались нулевыми. Обработка CPU-тега
  на P0 задаётся параметром `rd05_p0_cpu_tag`, `reseed` перезапускает
  интерфейс целиком; на AC8 работает `reboot`;
- `overlay/.../patches-6.6/330-*` — задержки RGMII порта CPU у RTL8367RB
  меняются на ходу (`/sys/module/rtl8365mb/parameters/ext_rgmii_*`);
- `ac8-ethtest` — подбор задержек RGMII и режима CPU-тега на роутере;
- `0007` — разбиение `firmware` создаёт `rootfs_data` после SquashFS, если
  раздел доступен на запись (профили 8/16 МБ открывают его через
  `realtek,writable-offset/size`);
- `0008` — вариант драйвера для AC8 собирается со слоем cfg80211 Realtek
  (`RTK_NL80211`, как в SDK Realtek для OpenWrt) вместо WEXT, против
  cfg80211 из mac80211 backports (API Linux 6.12): `link_id` в операциях,
  `wdev->links[]`, `cfg80211_ap_update`, `update_mgmt_frame_registrations`,
  регуляторный домен под `wiphy_lock`. Заголовки MadWifi `net80211` из SDK
  Realtek. `/etc/init.d/rtl8197f-wlan` грузит драйвер после старта системы
  и не грузит его снова после незавершённой загрузки;
- `overlay/.../patches-6.6/331-*` — ядро экспортирует `dev_change_name`:
  драйвер меняет местами имена VAP и клиентского интерфейса, как в ядрах
  SDK Realtek;
- `0009` — netifd раздаёт интерфейсам `rtl8192cd` имена, которые создаёт
  драйвер: `wlanN` (первая точка доступа), `wlanN-1`, `wlanN-2`…
  (как в OpenWrt до 23.05); остальным драйверам — как обычно;
- `overlay/.../patches-6.6/333-*` и `0010` — шина PCIe: RTL8197F включает
  `HAVE_PCI` (без него `CONFIG_PCI` молча выпадал из конфигурации),
  окно памяти хоста PCIe берётся из DTS с шинными адресами, равными
  физическим, как в стоке (BAR2 = `0x19000000`);
- `0011` — драйвер Wi-Fi поднимает оба радио: встроенное — через узел DTS
  `realtek,rtl8197f-wmac` с устройством для DMA API (в сборке с
  `CONFIG_NET_PCI` вендорский код его не запускал), RTL8812F — в
  5-ГГц-слоте, и в cfg80211 он регистрируется как 5 ГГц/802.11ac;
- `overlay/.../patches-6.6/332-*` — начальная настройка RTL8367RB из
  стоковой прошивки AC8 (`rtk_switch_init`): режим светодиодов портов,
  пороги управления потоком, SSC;
- светодиоды и кнопка — по GPIO из настроек стоковой прошивки AC8 v1
  (`sys_led=gpio6`, `wps_led=gpio7`, `reset_gpio=20`);
- `overlay/.../uci-defaults/90-ac8-network-leds` — переводит настройки,
  сохранённые со сборок до `ac8-20260924-13`, на `br-lan` + `wan` и убирает
  светодиоды `blue:wan`/`blue:lan`, которых больше нет;
- тема LuCI footstrap из фида `VizzleTF/luci-theme-footstrap` (закреплена на
  v0.14.13 в `scripts/prepare.sh`) становится темой по умолчанию.

## Что нужно проверить на железе

Значения ниже не подтверждены. Их правят в
`overlay/.../rtl8197f_tenda_ac8-v1.dtsi` по логам:

1. Раскладка флеша: `cs6c` по `0x20000` в дампе, где лежит конфигурация Tenda.
2. Объём ОЗУ: выводит загрузчик (`DRAM Size`).
3. ~~Выводы SMI коммутатора и канал к CPU~~ — подтверждены:
   `found an RTL8367RB-VB switch`, LAN работает с тегом `rtl8_4t` и
   задержками из `ac8-ethtest`. Осталось проверить WAN.
4. Какой порт коммутатора выведен на какое гнездо (одно из LAN-гнёзд —
   `lan4`).
5. PCIe: `10ec:f812` в `/proc/bus/pci/devices`.
6. Светодиоды SYS (A6) и WPS (A7): горят ли и не инвертированы ли; кнопка WPS/RST (C4).
7. Запись во флеш: сохраняются ли настройки после перезагрузки.
8. Wi-Fi: грузится ли драйвер (`/tmp/rtl8197f-wlan-load.log`), видны ли
   радио в `iw dev`/LuCI, поднимается ли точка доступа.
